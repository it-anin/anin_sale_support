ชื่อสินค้า / Generic Name — ให้เห็นข้อความครบ

เมนู Request Item หน้า SaleSupport · ตาราง .ss-table--request · 19 คอลัมน์

ป้ายมุมขวาของแต่ละการ์ด วัดจริงจากหน้าจอนี้ ว่า 2 คอลัมน์นั้นยังมีข้อความถูกตัดอยู่ไหม

ทำไมตอนนี้ถึงแคบ — เจอต้นเหตุแล้ว ไม่ใช่แค่ "ตั้งความกว้างน้อยไป"
MENUS['request'].columns กำหนด product_name: min 180 · generic_name: min 130 ไว้แล้ว และ JSX ก็ส่งลงไปเป็น style={{ minWidth: col.min }} จริง ๆ
แต่ App.css มี .ss-table th { min-width: 60px !important } — กฎที่มี !important ในสไตล์ชีตชนะ inline style ธรรมดา ค่า 180/130 จึงถูกทิ้งทั้งคู่ เหลือ 60px
ตารางเป็น table-layout: fixed คอลัมน์ที่ไม่ได้ประกาศ width จึงถูกหารพื้นที่เท่า ๆ กัน → ชื่อสินค้ากับ Generic Name ได้ความกว้างเท่าคอลัมน์ EXP หรือ Leadtime
หลักฐานว่าเป็นแบบนี้จริง: ทุกคอลัมน์ในตารางนี้ที่ "กว้างได้จริง" ต้องเขียน CSS แยกพร้อม !important เสมอ — c-status 118px · c-availability 132px · c-moq/c-sku 100px · ss-delete-col 54px (ถ้า inline min ใช้ได้ ก็ไม่ต้องมีกฎพวกนี้เลย)
ป้ายบอกชนิดข้างชื่อแบบ — แตะอะไรบ้าง
CSS อย่างเดียว แก้ App.css ไฟล์เดียว ไม่ต้องแตะ TSX · CSS + config ต้องแก้ MENUS ด้วย · ต้องแก้ JSX ต้องแตะโครง render ในตาราง
ป้ายวัด "ถูกตัดไหม" วัดจากของจริงในหน้านี้ — เทียบ scrollWidth กับ clientWidth ของทุกช่องใน 2 คอลัมน์นั้น ✅ แปลว่าไม่มีช่องไหนถูกตัด · ⚠️ แปลว่ายังมีช่องที่ถูกตัดอยู่ (แบบที่ตั้งใจให้ตัดแล้วไปโชว์เต็มตอน hover/คลิก ก็จะขึ้น ⚠️ เพราะตอนนิ่ง ๆ ยังตัดอยู่จริง)
ไฟล์นี้เป็นแกลเลอรีเทียบดีไซน์ ไม่ได้ import เข้าแอป — แบบที่ 1 "Widen" ถูกเลือกและใส่เข้าแอปแล้ว ที่เหลือเก็บไว้เทียบ
⚠️ ข้อมูลจริงในตารางตอนนี้มีแค่ 2 แถว (ชื่อยาวสุด 26 ตัวอักษร) — 2 แถวแรกด้านล่างคือของจริง อีก 3 แถวเป็นข้อมูลสมมติที่จงใจทำให้ยาว เพื่อทดสอบว่าพอชื่อยาวขึ้นแล้วแต่ละแบบยังไหวไหม
